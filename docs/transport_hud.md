# Transport HUD (Phase 11) — design & rationale

**Status: ✅ HW-CONFIRMED 2026-07-10 (PR fj#103, tested on the MiSTer with `DVD_hud_20260710_1955.rbf`)** — release build gated: clk_dec 91.07/88.12 MHz, ALM 90%, DSP unchanged. Known separate open issue: A/V sync off after a seek (pre-existing, see `docs/dvd_nav.md` §2a).

The release-visible playback feedback layer: transport icon, timecode, chapter
progress, track/angle popups, and the seek/progress bar — rendered in fabric
and composited through the existing `subpic_blend` stage. This is what makes
the "full DVD remote" of Phases 8–10 *visible*; the MiSTer OSD stays demoted
to hardware/setup toggles (see `docs/roadmap.md` "Phase 11").

Everything here was designed against two hard constraints:

1. **The display hotspot** (fabric corner X33_Y11..X44_Y22, shared with the
   clk_dec decoder paths — the chroma-fringe zone): only register-fed
   compares and flat muxes may sit in the per-pixel path. All string
   assembly, BCD math and division run at **event rate** in control logic.
2. **No new DSP** (97/112 used): the HUD priority-muxes into the **one
   existing** `subpic_blend` instance instead of instantiating a second, and
   the bar's division is a serial shift-subtract.

## Modules

### `dvd/transport_hud.sv` — status line + popups

Three layers:

- **Formatter (event rate):** every ~1.2 ms (and immediately after any event)
  it snapshots the input values and rewrites a **text plane** (2 rows × 32
  cells of `{accent, glyph[5:0]}`), one cell per cycle. BCD `dvd_time`
  nibbles map 1:1 to digit glyphs — no binary conversion anywhere; the only
  binary→BCD is the ≤99 chapter/track numbers (a compare-subtract chain).
  The snapshot prevents mid-string tearing; values that settle late (the
  reader's attr-BRAM language read) self-heal on the next pass.
- **Glyph ROM:** 64 glyphs × 16 rows × 8 px × 2 bpp = one M10K, generated by
  `tools/hud_font.py` → `dvd/hud_font.mem` (committed, plus a PNG preview
  sheet). Classes: 0 transparent, 1 outline (black), 2 fill (white, or amber
  when the cell's accent bit is set). Class-0 pixels of an *active* cell
  (glyph ≠ `G_NONE`) render as a translucent dark **backing** band so text
  reads over any video. Glyphs display at 2× (16×32 px on screen).
- **Pixel pipeline (display path):** 4 registered stages, a **pure function
  of `(core_h_pos, core_v_pos)`** — region hit-test → text-plane sync read →
  ROM sync read → class/colour resolve. The (x,y)-purity is the interlace
  safety proof: CRT-480i feeds the absolute frame line and gets identical
  pixels (asserted per-pixel by `hud_frame_tb`'s field-order pass). The
  pipeline latency rides a `HUD_QX_ADJ` column lead (default 5 = 4 module
  stages + emu's pre-blend register; HW-calibrate like `SP_QX_ADJ` — CRT's
  13.5 MHz pacing halves the effective lead, an imperceptible ~2 px shift).

**Status line** (bottom-anchored): `[icon] H:MM:SS/H:MM:SS CH n/N` — icon =
▶ / ❚❚ / ▶▶×n / ◀◀×n (scrub tier 0..3 shows ×1..×4; tiers are span-relative
step rates since PR fj#101, *not* seconds). `CH` hides until the reader's
`cur_pgm` query resolves (0 = unknown). Shown while: **persistent mode** (B9
"Display" toggles it), paused, scrubbing, or ~2.5 s after a transport event.

**Popup line** (above the bar): `AUDIO n/N LL` / `SUB n/N LL` / `SUB OFF` /
`ANGLE n/N` / `CH n/N` / `SEEK FWD MM:SS` — single slot, **last event wins**, own 2.5 s timer.
Languages come from the Phase-10 `attr_*` readout (2-ASCII ISO-639,
uppercased by the glyph mapper).

**Suppression:** the whole HUD hides while a menu is up (`menus_on &&
menu_active` — the HLI highlight layer owns the screen); persistent mode
survives and reappears on resume. A fresh media load clears everything.

**D-pad seek popup (`seek_evt`, 2026-08-27):** popup type **8** renders
`SEEK FWD  0:30` / `SEEK BACK 12:30` while an `O[45]` D-Pad Seek coalesce window is
open, so the running total is readable *before* the jump commits (`dpad_seek`
pulses `seek_evt` on every counted press). Arbitrated as a **user** event —
above the warnings, never preempted. Two things worth knowing:

- `pop_type`/`f2_type` were widened **3 → 4 bits** for this: all eight 3-bit
  encodings (0 aud, 1 sub, 2 angle, 3 chapter, 4 CSS, 5 image, 6 audio-fmt,
  7 VTS) were already spoken for.
- The sign is **spelled** (`FWD`/`BACK`), not punctuated, because the glyph ROM
  has no `+`. That keeps `tools/hud_font.py` and the committed
  `dvd/hud_font.mem` **untouched** — no regenerating a binary artifact, no new
  ROM content on a 91 %-RAM design. `FWD` is padded to `BACK`'s width so the
  digits land on fixed columns. The total renders as **MM:SS** (leading zero suppressed on
  the minutes; the second seconds digit is a literal `0`, because the accumulator only ever
  holds whole tens of seconds), so an arbitrarily long tap burst still reads exactly — up
  to `99:50`, which is what bounds the readout rather than the seek.

**Transport icon is shared (2026-08-27):** `scrub_held`/`scrub_dir`/`scrub_tier`
are muxed in emu — a **held** FF/REW scrub renders its accelerating tier, an open
**D-pad** coalesce window renders the tap COUNT, both as `►►×n` in the same field.
`hold_freeze` itself is untouched (it still pauses the governor/audio), which is
why a D-pad tap does not freeze video. See `docs/dvd_nav.md` §2b.

**Failed-menu-link popup (`link_evt`, 2026-08-27):** popup type **9** renders
`LINK FAIL nn` (accent label, `nn` = the unresolved PGCN clamped to 99, leading
zero suppressed; 0 for entry-scan targets) when `dvd_vm.link_fail` pulses — a
menu button's link did not resolve and the VM re-entered the current menu
instead of auto-playing the movie (see `docs/dvd_vm.md` "Failed-menu-link
re-enter"). Arbitrated as a **user** event (top of the event chain — it is rare
and it is the answer to "why did nothing happen") and **menu-exempt** like the
warnings, because it fires precisely while a menu is on screen. The debug
overlay's row 26 carries the reader's full reason latch for the same event.
Rendered with `a2g()` letters only — `hud_font.mem` untouched. Tests:
`transport_hud_tb` T21.

**CSS warning popup (`css_warn`, 2026-08-06):** popup type 4 renders
`CSS ENCRYPTED` (accent, cols 0–12) when emu's sticky `css_scrambled` latch is
set — the loaded image still carries CSS-scrambled sectors
(`PES_scrambling_control != 0` seen by `ps_demux`; such a rip decodes as green
macroblock garbage, so the popup is the "your rip isn't decrypted" diagnostic —
VLC plays these because libdvdcss decrypts on the fly; this core never sees CSS
keys by design). Two deliberate exceptions to the normal popup rules: it is
**persistent** (a level input, lowest priority — user popups take the slot for
their 2.5 s, then the warning re-arms) and it is **NOT menu-suppressed**
(scrambled discs green-screen in the menu domain first — that's where the user
is staring). Clears only on a fresh media mount. The same latch mutes both
audio paths (see `docs/fabric_audio.md` "CSS mute").

### `dvd/seek_bar.sv` — scrub feedback + progress popup

The **only** feedback for the Phase-8a seek-on-release scrub (PR fj#101):
while D-pad L/R is held the video is paused, so the bar's amber cursor is
how the user sees where the release lands. Fill = playhead at hold start
(`bar_base_rbn`), cursor = accumulating target (`bar_tgt_rbn`), shown while
`bar_active` (hold + scrub_ctrl's ~1.5 s linger). Position model =
sector/RBN against `title_first_rbn..title_last_rbn` (the roadmap's design:
monotonic, no TMAP, slight VBR nonlinearity accepted).

**Stretch (severable):** the bar also pops for 2.5 s on pause / landed seek /
chapter skip, showing the **live** playhead (`dsi_nv_pck_lbn`, no cursor)
with a notch at each chapter start. Tick columns come from **shadow copies**
of the reader's program map (the existing `pm_*` stream) and cell
first-sector table (a new `cellf_*` stream tap — deliberately a *write tap*,
not a new read port on the reader's BRAMs): on each `pgc_loaded` pulse a
converter walks `pmap[p] → cellf[pm−1] →` the shared divider `→ tick_col[p]`
once (~45 cycles per chapter). Severing the stretch = deleting the shadow
RAMs, converter, notch branch and the stream wires.

**Chapter-skip preview (✅ HW-CONFIRMED 2026-08-01, PR fj#153):** a B2/B3 chapter skip now gets
the **same amber cursor** as the scrub, parked on the projected target
chapter's start column. The HUD's "CH n/N" field already counted up live
through the ~500 ms multi-press debounce (`chap_disp_hold`/`chap_disp_act` in
`emu.sv`), but the bar stayed frozen at the live playhead — the number moved
and the timeline didn't, so a multi-chapter skip gave no sense of *where* it
was going. Because that chapter's start column is exactly `tick_col[n−1]`,
already converted for the notches, the preview is free: `chap_prev`/`chap_pgm`
inputs, one more sync read port on the tick list, and a registered cursor mux
(`curs_q`/`curc_q`) that keeps the display path's register→compare shape.
The scrub wins if both are up; the cursor falls silent when there is no tick
list (`tick_ok = 0`, e.g. linear `.VOB` playback) or the chapter is past its
end, and it clears when `chap_disp_act` drops (reader landed) so the **fill**
jumps to the new position. Fill stays the live playhead throughout — the bar
reads exactly like a scrub gesture: filled = where you are, cursor = where
you're going. `bench/dvd/seek_bar_tb.sv` T9.

**Math:** one free-running serial restoring divider,
`px = ((clamp(v) − first) << 9) / span` (0..512), alternating fill/cursor
(~3 µs per refresh vs scrub_ctrl's ~0.06 s tick) and serving tick conversion
after PGC loads. **Render:** 2-stage registered, (x,y)-pure except the
per-line **monotonic tick pointer** (the list is written ascending, so one
comparator walks it as the raster scans; it resets outside the bar region,
so field-order scanning is identical — and it needs a 1-cycle `tk_wait`
after each advance or the stale RAM read double-advances and skips a tick,
which the tb caught).

### `dvd/bcd_time_add.sv` — whole-title elapsed time

Combinational BCD `dvd_time` adder with a **rate-aware frame carry** (fps
from the b operand's rate bits: 25 PAL / 30 NTSC), verified against an
integer reference (8 directed + 500 random vectors). Two instances:

- **Reader prefix sum:** the P_CELL walker captures each cell's full
  `playback_time` (@4..7) and builds `cell_start_mem[i]` = the BCD sum of
  all *prior* cells' durations (self-initializing at cell 0; the adder
  evaluates once per 24-byte entry). `cur_cell_start` tracks the streaming
  cell on its **own** sync read port (`cell_raddr` is transiently repointed
  by the angle prefetch, so piggybacking would skew the readout).
- **emu display sum:** `cur_time = cell_ready ? cur_cell_start (+)
  dsi_c_eltm : dsi_c_eltm` — whole-title elapsed, falling back to bare
  cell-relative time for linear (non-ISO) playback.

## Compositing & layer order

The HUD/bar outputs are already registered inside their modules; emu's
existing `sp_*_q` register stage gains a priority mux (the **only** hotspot
edit): `HUD text > seek bar > subtitle/HLI highlight`, with `force` set so
the idx0 transparency key can't drop them. Above everything else the
`dbg_blk*` diagnostics and the `DEBUG_OVERLAY` build keep their place at the
final `vga_*_q` mux.

Geometry (both NTSC 480 and PAL 576, bottom-anchored, inside CRT overscan):

```
popup row   activeH-112 .. -81    (AUDIO 2/4 FR ...)
seek bar    activeH-78  .. -69
status row  activeH-64  .. -33    (> 0:12:34/1:37:05 CH 12/23)
            x = 104 .. 615 (512 wide, matches all three)
```

## Known limitations / follow-ups

- **HDMI-480i (O9):** pixel-repetition renders the HUD half-width — the same
  un-fixed subtitle caveat; folds into the shared `q_x`-halving follow-up.
  (CRT-480i and all progressive modes are correct.)
- **Time readout leads the picture** by the VBUF depth (~1 s): `dsi_c_eltm`
  is parse-front-timed (Phase-7 characteristic, inherited).
- **Multi-angle titles over-count** the whole-title total per-cell prefix sum
  (all angles' cells are summed). The *elapsed* time is also parse-front; the
  MiB FX featurette is the HW test vehicle.
- **`cur_pgm` query walk** shares the chapter FSM: a real skip pre-empts an
  in-flight query (discarded, re-fires after the landing cell change).
- Tick columns cap at 100 chapters (`tick_col[0:99]`); ticks closer than
  ~3 px apart may drop (pointer advances 1 per 2 cycles) — irrelevant for
  real chapter spacing.
