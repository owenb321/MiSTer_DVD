# Committed cosim test vectors

Unlike `tools/streams/` (gitignored, regenerated by `tools/gen_test_stream.sh`
with ffmpeg), these AC-3 streams are **committed** because they cannot be
produced by ffmpeg — its AC-3 encoder emits **long blocks only**.

## `bbb_short_5p1.ac3` — short-block + ch0-uncoupled vector (M16 + coupling fix)

An 11-frame (19 KiB) extract of the 5.1 / 448 kb/s AC-3 track from the
**Big Buck Bunny** NTSC DVD (frames 634..644 of the full track), centred on
**frame 639 (~20.4 s)** — the exact point the decoder used to halt on hardware.
This window deliberately exercises two real-DVD features ffmpeg cannot generate:

1. **Short (256-pt) transform blocks** (`blksw==1`) — block switching on
   transients (the M16 short IMDCT path).
2. **Coupling with ch0 *uncoupled*** — frame 639 changes the coupling strategy
   per block (`chincpl` 31→29→28→30→…), so in some blocks the first *coupled*
   channel is not ch0. This caught a pre-existing `mantissa_dequant` bug (the
   shared coupling mantissas were read only when `ch==0`, desyncing when ch0 is
   uncoupled — all earlier coupled vectors had `chincpl=31`). Fixed alongside M16.

`run_front_cosim.sh` golden-checks the dut against liba52 (geometry / exps / bap
**bit-exact**, frame stays synced through all 6 blocks; PCM **informational**,
because real full-band content is fixed-point-IMDCT-precision-limited — the same
basis on which `noise_5p1` PCM is informational, see roadmap M14 Stage D2).

The short IMDCT *arithmetic* is gated bit-bounded separately by the standalone
unit test `run_imdct256.sh` (vs liba52 `a52_imdct_256`, two blocks with a carried
delay line).
